# GenAI Usage Appendix

## Declaration

Generative AI was used in a declared way throughout this coursework. It was used to accelerate planning, implementation support, documentation structuring, presentation preparation, and final compliance checking. Final responsibility for design decisions, code review, file selection, testing, and submission remained with the project author.

## Tools Used

- AI assistant for planning the architecture and implementation sequence
- AI assistant for refining API structure, documentation scaffolding, and testing scope
- AI assistant for drafting supporting written materials

## Method of Use

- Project planning and decomposition
- Reviewing model boundaries and API grouping
- Drafting documentation structure
- Generating candidate implementation approaches for ingestion, recommendation, and analytics
- Improving wording and structure for submission-facing materials

## Accepted AI Contributions

- Requirement extraction from the coursework PDF into a structured checklist
- Topic selection refinement from a generic API to a book recommendation and analytics API
- Suggesting a rule-based recommendation design that was practical within the available timeframe
- Proposing a staged git commit structure aligned with the final repository contents
- Drafting first-pass report, API documentation, and presentation structure

## Modified AI Contributions

- Initial plans were reduced to a tighter scope to fit a two-day delivery window
- Documentation outputs were rewritten to include coursework-specific links and deliverables
- Presentation coverage was expanded to include version control, API documentation overview, report highlights, deployment, and GenAI usage
- Recommendation behavior was kept explainable rather than following more complex but higher-risk ML suggestions

## Rejected or Limited AI Contributions

- Heavy machine learning or collaborative filtering approaches that would have been hard to justify and test in the available time
- Overly broad commit histories that would have looked artificial rather than feature-driven
- Documentation wording that described future work without first satisfying required deliverables

## Oversight and Validation

- Final implementation decisions were reviewed before being applied
- Code and documentation were checked locally
- Project-specific tradeoffs were chosen manually
- Unsupported or weak suggestions were discarded rather than accepted automatically
- Tests, schema export, asset generation, and repository checks were used to validate outcomes
